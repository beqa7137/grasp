# Improvement loop

The loop's memory between runs. Each run reads this first, picks one item, ships it through the full release sequence in
`CLAUDE.md` into `feature/improvements` (the loop's base branch; production and `main` only on the owner's request), and
updates this file in the same change: add a line to **Shipped**, remove or edit what it resolved, and add any follow-ups
it found. Keep entries short and factual, with numbers where they exist.

## Open follow-ups

- Iterations 19 to 25 were built by Codex on `feature/improvements-codex` and fast-forwarded into `feature/improvements` after an independent Claude review; iteration 26 on continues there without Codex. The owner clarified the capacity target as 100,000 simultaneous active users. Its priority is production readiness for that concurrency, followed by deeper, reviewed algorithms and system-design lessons and practice. Registered-account counts and local rehearsals do not prove this target; wider-release claims require a defined workload and distributed production-like measurements. The owner excludes older-client compatibility from new work; preserve existing learner data without adding legacy transport paths.
- JavaScript Sentry reporting now uses an explicit capture and transport allowlist. Native crash uploads are temporarily disabled because JavaScript callbacks cannot filter native envelopes. Restore them only with native filtering and crash/relaunch, offline replay and prior-cache verification. The API uses explicit sanitized reports only, so automatic unhandled-process Sentry capture is disabled.
- Before promoting iteration 21, drain or disable all older paid API instances, finish their provider calls and protect older deployment URLs. The additive ledger migration imports old totals, but old code cannot see reservations or new charges. Rolling back to old admission logic requires disabling paid traffic. Conservative full-context reservations also require headroom for concurrent attempts; see `docs/DEPLOYMENT.md`.
- Iteration 22 changes route counter keys and authentication limits. During a mixed-version rollout, route allowances split and older instances retain small per-IP auth buckets. Retire them before relying on classroom fairness. The 1,200-per-minute network cap is per auth endpoint and still allows fixed-window bursts; the local 1,000-account rehearsal is not production capacity certification. Public anonymous routes still share their existing per-IP buckets. Iteration 23 closes guest paid access through verified accounts and explicit AI selection; account deletion/recreation and additional verified accounts are not one-human entitlement controls.
- Third-party console logging still needs review: the installed social-login plugin logs raw storage parse errors, and Capacitor logs raw bridge failures. The application-owned error handlers and outbound Sentry reports are filtered; do not claim every dependency console message is private.
